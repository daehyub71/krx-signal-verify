## 병렬 진행 가능 구간 (2026-09-05 검토)

마일스톤 번호는 **우선순위이지 의존관계가 아니다.** 실제로 서로를 막는 것만 아래처럼 묶었다.

| 표시 | 뜻 |
|------|-----|
| `⇉A` | **레인 A — 바깥에서 받아 오는 일** (REST·MCP·상위 DB). 다른 레인과 겹치지 않는다 |
| `⇉B` | **레인 B — 순수 도메인** (계산·판별). 픽스처만 있으면 I/O 없이 쓴다 |
| `⇉C` | **레인 C — 저장·배선**. M2와 무관하다 (아래 근거 참조) |
| `⏸` | **사용자에게 달렸다** — 내가 못 여는 문. 달력 시간이라 먼저 열어 둘수록 좋다 |

### 근거 — M3를 M2와 병렬로 둘 수 있는 이유

M2가 채우는 **재무·공매도는 점수에 들어가지 않는다.** `judge()`에서 그 둘은
`_blind_spots()`만 건드리고 `parts`에는 닿지 않는다 (SPEC F30·F32 「표시는 사실만」,
V5 「가중치는 사람이 SPEC을 고쳐서만」).

**2026-09-05 실행으로 확인:** 같은 입력에 `financial`·`shorting`을 넣기 전과 후가
`stand=불일치 · score=20 · parts` **전부 동일**하고 `blind_spots`만 여덟 → 여섯으로 줄었다.

→ **오늘 저장한 판정은 M2가 끝난 뒤의 판정과 같은 자로 잰 값이다.**
그리고 소급하지 않기로 했으므로(V13) **저장이 하루 늦으면 60거래일 분포도 하루 늦는다.**
M3는 미루는 만큼 손해가 나는 유일한 마일스톤이다.

### 지금 열 수 있는 세 갈래

```
⏸  사용자 결정          M3.5 승인 ─────────────→ M4 전체를 막고 있다
                        M7 DESIGN 시안 합의 ───→ M7 전체를 막고 있다
                        M8 승인 (급하지 않다 — 공매도는 없어도 되는 층)

⇉A  바깥에서 받아 오기   dart_fin.py → enrich.py
⇉B  순수 도메인          financial.py (+F31)          ┐ 픽스처 3종을 먼저 고정한 뒤
⇉C  저장·배선            M3 판정 저장 (7개)           ┘ 세 갈래가 서로를 안 기다린다
```

**합류 지점** — M2의 `F34`와 `손검증`은 A·B가 둘 다 끝나야 한다. M3의 왕복 테스트는 C 안에서 닫힌다.

**선행 조건 하나** — 레인 B를 열려면 **픽스처를 먼저 뜬다**: ① 일반 회사 `fnlttMultiAcnt.json`
응답 ② **금융사** 응답(F31의 근거) ③ 상위 수급·시세 SQL 결과 모양. 이게 A와 B의 **공유 계약**이고,
없이 시작하면 계정 이름을 추측하게 된다.

### 병렬로 두지 **않는** 것

- **`shorting.py`** — `ksc_shorting`이 아직 없다(2026-09-05 확인). SPEC F32도 「상위가 수집하면」이라
  스키마가 안 정해졌다. 지금 쓰면 **상상한 스키마에 맞춰 파싱을 짓게 된다.**
  **「없는 층」으로 흐르는 경로만** 지금 만들고, 파싱은 M8 승인 뒤로 미룬다.
- **M4** — `ksc_index_bars`가 없다. TASKS가 「이게 서기 전에는 M4를 시작하지 않는다」고 못 박았고,
  그 결정을 우회하지 않는다. (거래정지일 배제 로직만은 지수와 무관하지만, 반쪽으로 두면
  나중에 다시 읽어야 한다.)
- **M5·M6** — `notify.py`(Gmail SMTP)와 워크플로 YAML은 기술적으로 지금도 되지만,
  **보낼 것이 없는 상태에서 만들면 실물 확인을 못 한다.** 이 프로젝트에서 값이 나온 것은
  전부 실물 확인에서였다.

- [x] **① SPEC §5 RLS 문구 수정** — 「다섯 테이블 모두 RLS를 켜고 **정책을 만들지 않는다**」와 V9의 「`ksv_reader`에 `GRANT SELECT`」는 함께 성립하지 않는다. PostgreSQL은 RLS가 켜진 테이블에 정책이 하나도 없으면 소유자·슈퍼유저·`BYPASSRLS` 외 **모든 롤에 0행**을 준다. 선행 `ksb_*`가 이 구성으로 도는 것은 배치가 service_role(BYPASSRLS)을 쓰기 때문이고, V9는 그 우회를 버리기로 한 결정이다. → **「`to anon` 정책은 만들지 않는다 · `to ksv_reader` SELECT 정책만 만든다」**로 고친다 → **반영.** SPEC §5를 「`to anon` 금지 · `to ksv_reader` SELECT 정책은 만든다」로 고치고, 정책 없는 RLS가 왜 모든 롤을 막는지 SQL 예시와 함께 적었다. N11·§9 #10·PLAN §4-1·§7 `test_schema`까지 함께 (검사 기준이 「정책 0개」가 아니라 **「anon 0개 + reader 존재」**)

  - ⚠ **문서 테스트가 느슨했다** — 「그 말이 어딘가 있으면 통과」라 절차를 통째로 지워도 안 깨졌다(변이 검사로 드러남). 순서와 한 문장 안의 조합까지 보게 조였다

**완료 기준** — 배치가 도는 날마다 `ksv_verdicts`에 그날 판정이 `parts`·`blind_spots`·`rules_version`과 함께 남는다 · **멱등 재실행이 열을 지우지 않는다**(왕복 테스트) · 청크 저장 실DB 확인. **소급 표본은 완료 기준이 아니다**
